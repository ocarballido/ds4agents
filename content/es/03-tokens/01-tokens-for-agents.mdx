Un token es una decisión de diseño con nombre. Para un agente, la diferencia entre `#1C64D9` y `color.action.primary` es la diferencia entre copiar un color y entender para qué sirve. Este capítulo trata lo que el agente necesita de tus tokens; cómo se construye el sistema completo lo explica DesignToken101.

## Del valor a la decisión

La especificación DTCG define un token como información asociada a un nombre legible por personas, y presenta los tokens como una forma de compartir decisiones de diseño entre herramientas y tecnologías ([Format Module: Introduction](https://www.designtokens.org/TR/2025.10/format/#introduction)).

La guía de Figma para el servidor MCP pide usar variables para el espaciado, el color, el radio y la tipografía, para que el agente haga referencia a tus tokens en lugar de copiar valores ([Figma: Structure your Figma file for better code](https://developers.figma.com/docs/figma-mcp-server/structure-figma-file/)). La herramienta `get_variable_defs` devuelve las variables y estilos de una selección ([Figma: Tools and prompts](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/)).

Un agente que recibe un valor suelto puede reproducir el diseño. Uno que recibe un token puede, además, mantenerlo: si cambia la marca o el modo, el código generado sigue funcionando.

## Lo que este capítulo añade

Para un agente, un sistema de tokens bien construido necesita dos cosas más:

1. **Una regla de uso clara:** qué capa de tokens puede usar y cuál no. Lo vemos en [Primero los semánticos](/tokens/semantic-first).
2. **La intención escrita en cada token:** para qué sirve y para qué no. Lo vemos en [Descripciones en DTCG](/tokens/descriptions-in-dtcg).

Si tu sistema todavía no tiene tokens, empieza por [DesignToken101](https://designtokens101.com) y vuelve aquí.

<Takeaways>

## En resumen

- Un token da al agente el nombre y la intención, no solo el valor.
- El recorrido de Figma al código lo explica DesignToken101 paso a paso.
- Para un agente faltan dos cosas: una regla de capas y una descripción en cada token semántico.

</Takeaways>
