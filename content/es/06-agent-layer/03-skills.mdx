## Qué es una skill

Una skill es una carpeta con un archivo `SKILL.md`: un frontmatter YAML que dice cuándo usarla y un cuerpo con las instrucciones. Puede llevar archivos de apoyo, como plantillas o scripts. Las skills de Claude Code siguen el estándar abierto Agent Skills, que funciona en varias herramientas de IA ([Claude Code: Skills](https://code.claude.com/docs/en/skills)).

Claude Code recomienda pasar a una skill cualquier entrada de `CLAUDE.md` que sea un procedimiento de varios pasos ([Claude Code: Memory](https://code.claude.com/docs/en/memory)).

| Ubicación | Ruta | Se carga en |
|---|---|---|
| Proyecto | `.claude/skills/<nombre>/SKILL.md` | Las sesiones de ese repositorio |
| Personal | `~/.claude/skills/<nombre>/SKILL.md` | Todos tus proyectos |
| Plugin | `<plugin>/skills/<nombre>/SKILL.md` | Donde el plugin esté activo |

Fuente: [Claude Code: Skills](https://code.claude.com/docs/en/skills).

## Cómo se escribe

Lo que dice la documentación de Claude Code ([Claude Code: Skills](https://code.claude.com/docs/en/skills)):

- **`description`** es el campo recomendado: Claude lo usa para decidir cuándo aplicar la skill. Conviene poner primero el caso de uso principal, porque la lista de skills recorta las descripciones largas.
- **Menos de 500 líneas** en `SKILL.md`. El material de referencia va a archivos aparte, enlazados desde `SKILL.md` para que Claude sepa cuándo abrirlos.
- **`disable-model-invocation: true`** impide que Claude use la skill por su cuenta; solo se ejecuta con `/nombre`. Es para procedimientos con efectos, como publicar.

En nuestra prueba del 1 de noviembre de 2026, una sesión nueva de Claude Code cargó sola la skill de crear interfaces por su descripción, sin nombrarla en la petición, pero se saltó su primer paso ([Una primera prueba](/agent-layer/checklist#una-primera-prueba)).

## Las skills de Figma

Figma publica skills oficiales para agentes. Entre ellas, `figma-use` (escribir en el lienzo de Figma con los componentes y variables del equipo), `figma-code-connect` (conectar componentes publicados con su código), `figma-spec` (leer y escribir Figma Specs) y dos de ejemplo, `figma-generate-library` y `figma-generate-design`, que sirven tal cual y como plantilla ([Figma: Figma's agent skills](https://help.figma.com/hc/en-us/articles/39166810751895)). En Claude Code se instalan con el plugin de Figma ([Figma: Remote server installation](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/)).

El servidor MCP de Figma tiene, además, un *prompt* llamado `create_design_system_rules` que genera un archivo de reglas para que el agente produzca código que encaje con tu código y tu sistema. Figma propone guardar el resultado en una carpeta `rules/` o `instructions/` del proyecto ([Figma: Tools and prompts](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/)).

<Callout variant="recommendation">

Usa `create_design_system_rules` como borrador, no como resultado. Compara lo que genera con tu `AGENTS.md` y tu carpeta `docs/`, y quédate solo con lo que falte. Si lo guardas tal cual, tendrás dos versiones de las mismas reglas.

</Callout>

## Skills en el agente de Figma

El agente de Figma, en Figma Design y en Figma Make, también usa skills. Lo que dice la ayuda de Figma ([Figma: Create and manage custom skills in Figma](https://help.figma.com/hc/en-us/articles/40283639496599-Create-and-manage-custom-skills-in-Figma)):

- Son archivos Markdown que siguen la especificación Agent Skills, como las de Claude Code. Cada skill es un solo archivo: no admite las carpetas opcionales `scripts/`, `references/` ni `assets/`.
- Se crean en el chat del agente de tres maneras: pidiéndosela al agente, subiendo un archivo `.md` o escribiéndola a mano. Sirven en todos tus archivos, no solo en el que las creaste.
- Se invocan con `/` y su nombre. Si un *prompt* nombra varias, solo se invoca la primera.
- Se pueden publicar para un equipo, una organización o Figma Community, y exportar como Markdown.
- Están en todos los planes. Con asiento Full se usan en cualquier archivo; con View, Dev o Collab, solo en Drafts.

Para escribirlas, Figma pide dos cosas. La condición de uso se escribe como un requisito ("úsala siempre que…"), no como una restricción ("úsala solo si…"). Y si la vas a publicar, lleva un nombre propio, con el de tu equipo o tu empresa, para que no choque con otra skill del mismo nombre.

La ayuda dice que una skill se invoca con su comando, pero también habla de skills que se invocan automáticamente. No aclara si el agente de Figma elige una skill por su descripción, como hace Claude Code.

<Callout variant="recommendation">

Las skills de crear y revisar interfaces de esta página leen archivos del repositorio (`docs/`, `AGENTS.md`) que el agente de Figma no tiene. Para el agente de Figma, escribe una skill aparte que ordene los pasos con lo que sí recibe: los componentes y las variables de la librería, sus descripciones, los ejemplos y las guidelines. Las reglas siguen en `docs/` y le llegan por las guidelines ([Una fuente, varios destinos](/documentation/one-source-many-channels)): la skill no las repite.

</Callout>

## Skill para crear interfaces

```markdown filename=".claude/skills/build-ui/SKILL.md" preview
---
name: build-ui
description: Crear o modificar pantallas y componentes de interfaz con el sistema de diseño Acme. Usar cuando se pida construir una vista, un formulario o una página, o implementar un diseño de Figma.
---

# Crear interfaces con el sistema Acme

1. Lee `docs/inventory.md` para saber qué componentes existen y cuáles están obsoletos.
2. Busca en `docs/patterns/` un patrón que encaje. Si existe, sigue su receta.
3. Si hay un enlace de Figma, usa el MCP de Figma: contexto de diseño, variables y Code Connect.
   Trata el código que devuelve como referencia del diseño, no como código final.
4. Lee el documento de cada componente que vayas a usar y comprueba sus props.
5. Sustituye cualquier valor literal por su token semántico.
6. Antes de terminar, ejecuta la skill review-ui.

Si falta un componente o un token, no lo inventes: explica qué falta y propón la composición más cercana.
Si Figma y `docs/` no coinciden, manda `docs/`; señala la diferencia.
```

## Skill para revisar interfaces

```markdown filename=".claude/skills/review-ui/SKILL.md" preview
---
name: review-ui
description: Revisar una interfaz o un conjunto de cambios contra las reglas del sistema de diseño Acme. Usar antes de terminar cualquier tarea de interfaz o cuando se pida una revisión de diseño.
---

# Revisión contra el sistema

Revisa los archivos cambiados y devuelve una tabla: regla, archivo y línea, problema, corrección.

- Ningún color, espaciado ni radio literal (busca #, rgb( y px fuera de tokens/).
- Ningún import de componentes con status deprecated.
- Todas las props usadas existen en el documento del componente.
- Máximo un Button variant="primary" por vista.
- Todo TextField tiene label.
- Los textos siguen docs/content/voice-and-tone.md.
```

<Takeaways>

## En resumen

- Una skill es un `SKILL.md` con una descripción que dice cuándo usarla y las instrucciones del procedimiento.
- Figma publica skills oficiales para otros agentes, y su propio agente usa skills de un solo archivo que se invocan con `/`.
- Dos skills cubren lo esencial: crear interfaces con el sistema y revisarlas contra sus reglas.

</Takeaways>
