## Figma

| Función | Plan | Asiento o permiso | Fuente |
|---|---|---|---|
| Modos de variables | Professional, Education, Organization o Enterprise | Edición del archivo | [Figma: Modes for variables](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables) |
| Descripciones de componentes, estilos y variables | La ayuda no indica límite de plan | Edición de la librería | [Figma: Add descriptions](https://help.figma.com/hc/en-us/articles/7938814091287) |
| Anotaciones | De pago | Full para añadirlas; Full o Dev para verlas | [Figma: Add measurements and annotate designs](https://help.figma.com/hc/en-us/articles/20774752502935-Add-measurements-and-annotate-designs) |
| Dev resources | De pago | Full o Dev | [Figma: Dev resources](https://help.figma.com/hc/en-us/articles/15023231995927) |
| Guidelines de librería (beta abierta) | Professional, Organization o Enterprise | Edición del archivo; consume créditos de IA | [Figma: About guidelines](https://help.figma.com/hc/en-us/articles/43509372175511) |
| Code Connect | Professional, Organization, Government o Enterprise | Full o Dev | [Figma: Code Connect](https://help.figma.com/hc/en-us/articles/23920389749655-Code-Connect) |
| Servidor MCP de Figma | Starter, Professional, Education, Organization, Government o Enterprise | El servidor de escritorio pide Dev o Full; los límites de uso dependen del plan y del asiento | [Figma: Figma MCP server](https://help.figma.com/hc/en-us/articles/32132100833559) |
| Analíticas de librería | Organization o Enterprise | Ver o editar la librería | [Figma: Library analytics](https://help.figma.com/hc/en-us/articles/360039238353-Track-library-and-component-usage) |

<Callout variant="warning">

En Professional, Code Connect permite una sola librería y un solo framework activos, y el servidor MCP solo devuelve las conexiones de esa librería y ese framework ([Figma: Code Connect integration](https://developers.figma.com/docs/figma-mcp-server/code-connect-integration/)).

</Callout>

<Callout variant="note">

Las analíticas de librería solo existen en Organization y Enterprise. En otros planes, la [auditoría](/audit/figma-inventory) se hace a mano, recorriendo la librería.

</Callout>

## Código

Los capítulos 5 a 7 suponen que el sistema tiene una librería de componentes en un repositorio. Para seguirlos necesitas:

- Un repositorio Git con la librería de componentes.
- Node.js y un gestor de paquetes, para Code Connect por línea de comandos y Storybook.
- Si usas Storybook con agentes: un proyecto con React (cualquier framework de React), `angular-vite` o `vue3-vite`. Con otros frameworks, el servidor MCP de Storybook funciona, pero sin el manifiesto de componentes ([Storybook: MCP server](https://storybook.js.org/docs/ai/mcp/overview)).

<Callout variant="recommendation">

La documentación del sistema (la carpeta `docs/` del [capítulo 4](/documentation/why-markdown#la-carpeta-docs)) vive en la raíz del repositorio de la librería de componentes, junto a `src/`, `tokens/` y la configuración de Storybook. El script de validación comprueba rutas de código, y `CLAUDE.md`, las skills y Code Connect están en ese mismo repositorio.

- Si la web de documentación del sistema está en otro repositorio, consume la carpeta `docs/` de la librería; no mantiene una copia.
- Si tu equipo aún no tiene código, los capítulos 1 a 4 se pueden seguir con un repositorio solo de documentación y tokens. Cuando exista la librería, `docs/` se mueve a ella.

</Callout>

## Conocimientos previos

- **Imprescindible:** manejo de componentes, propiedades de componente, auto layout y variables en Figma.
- **Útil:** haber escrito documentación en Markdown.
- **Para los capítulos 5 a 7:** terminal y Git básicos.
- **Para los tokens:** si nunca has trabajado con tokens de diseño, empieza por [DesignToken101](https://designtokens101.com).

<Takeaways>

## En resumen

- Las guidelines y Code Connect piden Figma Professional o superior; las analíticas, Organization o Enterprise.
- Claude Design está en todos los planes de Claude; los sistemas de diseño, en beta, desde Pro.
- Los capítulos 5 a 7 dan su mejor resultado con una librería de componentes en un repositorio.

</Takeaways>
